# Googleカレンダー連携（正規運用）作業手順書

本アプリで任意のGoogleアカウントから安全にGoogleカレンダーへ予定を登録できるよう、Google Cloud Console で実施する正規のOAuth設定・公開手順をまとめたものです。

> [!IMPORTANT]
> 本アプリはブラウザー完結型のため、Google Identity Services（GIS）によるフロントエンド認証を使用します。**クライアントシークレットは使用せず、ブラウザーにも埋め込みません。**

---

## 0. 事前に用意するもの

本番公開（正規連携）および Google のアプリ審査では、以下の公開情報が必要になります。

1. **アプリを公開する本番URL（HTTPS）**
   - 例: `https://example.com`（独自ドメイン推奨）
   - ※ GitHub Pages や Vercel 等の無料ドメインを使う場合でも、所有権確認が可能な環境が望ましいです。
2. **プライバシーポリシーの公開URL**
   - 本番サイト内にページを用意し、以下を明記します。
     - 取得する情報（Googleカレンダーへの予定登録権限のみ）
     - 利用目的（点眼ルーティンの完了履歴を本人のGoogleカレンダーへ記録するため）
     - 外部サーバーへの送信・保存を行わないこと（設定・履歴は利用者のブラウザー内のみに保存）
3. **利用規約の公開URL**（推奨）
4. **アプリのアイコン画像**（120×120px 以上の PNG / JPG）
5. **連絡先メールアドレス**（サポート用・デベロッパー連絡用）

---

## 1. Google Cloud プロジェクトの作成

1. [Google Cloud Console](https://console.cloud.google.com/) にログインします。
2. 画面上部のプロジェクト選択ドロップダウンから **「新しいプロジェクト」** をクリックします。
3. プロジェクト名（例：`eyedrops-timer`）を入力して **「作成」** をクリックし、作成したプロジェクトを選択状態にします。

---

## 2. Google Calendar API の有効化

1. 左側メニューから **「APIとサービス」＞「ライブラリ」** を開きます。
2. 検索欄で `Google Calendar API` を検索し、選択します。
3. **「有効にする」** ボタンをクリックします。

---

## 3. OAuth 同意画面の設定

1. 左側メニューから **「APIとサービス」＞「OAuth 同意画面」**（または「Google Auth Platform」）を開きます。
2. User Type で **「外部」** を選択して **「作成」** をクリックします。
3. **アプリ情報** を入力します。
   - **アプリ名**: `点眼タイマー`
   - **ユーザーサポートメール**: 自身のメールアドレス
   - **アプリのロゴ**: 用意したアイコン画像をアップロード
4. **アプリのドメイン** を入力します。
   - **アプリケーションホームページ**: 本番URL（例：`https://example.com`）
   - **アプリケーションのプライバシーポリシーリンク**: プライバシーポリシーURL
   - **アプリケーションの利用規約リンク**: 利用規約URL（用意した場合）
5. **承認済みドメイン** に本番URLのドメイン（例：`example.com`）を追加します。
6. **デベロッパーの連絡先情報** にメールアドレスを入力し、保存して次へ進みます。

---

## 4. スコープの設定

1. **「スコープを追加または削除」** をクリックします。
2. 最小権限の原則に基づき、以下のスコープのみを選択して追加します。
   - `https://www.googleapis.com/auth/calendar.events`（カレンダーの予定の表示および編集）
   - ※ カレンダー全体へのフルアクセス（`.../auth/calendar`）は不要であり、審査のハードルが上がるため選択しません。
3. 保存して次へ進みます。

---

## 5. OAuth クライアント ID の作成

1. 左側メニューから **「APIとサービス」＞「認証情報」** を開きます。
2. 上部の **「認証情報を作成」＞「OAuth クライアント ID」** をクリックします。
3. 以下を設定して **「作成」** をクリックします。
   - **アプリケーションの種類**: `ウェブ アプリケーション`
   - **名前**: `点眼タイマー Web`（任意）
   - **承認済みの JavaScript 生成元**:
     - 本番URL（例：`https://example.com`）
     - 開発・検証用URL（例：`http://localhost:8080`）
   - **承認済みのリダイレクト URI**: GISのポップアップ／トークン方式のみを使う場合は空欄で可（必要に応じて本番URLを設定）。
4. 発行された **クライアント ID**（`xxxxxxxx.apps.googleusercontent.com`）を控えます。

---

## 6. 公開前の動作確認（テストユーザー）

本番公開を行う前に、テスト状態で動作確認を行います。

1. 「OAuth 同意画面」の **「テストユーザー」** に自身のGoogleアカウントを追加します。
2. プロジェクトルートの `.env.example` を `.env` にコピーし、手順5で取得した **クライアント ID** を設定します。
   ```env
   GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
   ```
3. `node scripts/generate-config.mjs` を実行して `public/js/env.js` を生成します（Apache2 公開時は `sudo bash scripts/setup-apache2.sh` 実行時にも自動生成されます）。
4. アプリを起動し、ルーティン完了画面から「Googleカレンダーに記録」を実行して、`primary` カレンダーに予定（ルーティン名・開始時間・終了時間）が登録されることを確認します。

---

## 7. 本番公開と Google アプリ審査（Verification）

不特定多数の利用者が警告画面（「このアプリは Google で確認されていません」）なしで正規に連携できるようにするため、アプリを公開して審査を受けます。

### 7.1 ドメインの所有権確認
1. [Google Search Console](https://search.google.com/search-console) に本番URLのドメインを登録し、DNSレコード等で所有権を確認しておきます（同一Googleアカウントで実施すると審査がスムーズです）。

### 7.2 デモ動画の撮影
`calendar.events` スコープは機密性の高いスコープ（Sensitive Scope）に該当するため、審査申請時に **動作デモ動画（YouTube限定公開リンク等）** の提出を求められます。以下の流れを1本の動画に収めてください。

1. アプリの本番URLにアクセスする様子
2. 「Googleカレンダーに保存」を押下し、Googleログイン〜**OAuth同意画面（URLバーにクライアントIDが見える状態、およびスコープ許可画面）** を操作する様子
3. 登録完了後、Googleカレンダーを開いて実際に予定が作成されたことを確認する様子

### 7.3 本番公開・審査提出
1. Google Cloud Console の「OAuth 同意画面」を開き、公開ステータス横の **「アプリを公開」** をクリックして **「本番環境」** に切り替えます。
2. 画面の指示に従い、**「確認の準備」**（審査申請）へ進みます。
3. 以下の項目を入力・提出します。
   - スコープ（`calendar.events`）が必要な理由の説明（例：「点眼ルーティンの完了履歴をユーザー本人のGoogleカレンダーに予定として記録するため。読み取りや削除、他者への共有は行いません。」）
   - デモ動画のURL
4. 審査完了のメール通知が届いたら、テストユーザー以外のアカウントでも警告画面なしで正規に連携できることを確認して完了です。

## チェックリスト

- [ ] 本番URL（HTTPS）とプライバシーポリシーページを公開した
- [ ] Google Calendar API を有効化した
- [ ] OAuth 同意画面にアプリ名・ドメイン・プライバシーポリシーを設定した
- [ ] スコープを `https://www.googleapis.com/auth/calendar.events` のみに限定した
- [ ] ウェブアプリケーション用 OAuth クライアント ID を発行し、JavaScript 生成元を設定した
- [ ] クライアント ID をアプリへ反映し、テストユーザーで登録動作を確認した
- [ ] Search Console でドメイン所有権を確認し、デモ動画を用意した
- [ ] 「アプリを公開」を実行し、Google の確認（審査）を通過した
